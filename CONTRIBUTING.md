## 中文

### 如何报 Bug

1. 先在 Issue 中搜索，确认问题未被报告。
2. 新开 Issue 时请提供：
   - 问题描述与复现步骤（最小化路径最佳）；
   - 运行环境（Node 版本 ≥ 20、操作系统、浏览器及版本）；
   - 预期行为 vs 实际行为；
   - 报错日志或截图（涉及 Mermaid 图渲染问题时，请附上对应图的图号与项目 ID）。

### 内容纠错（数据与文档）

本站内容按项目分文件维护：

- 每个项目的深度内容（四张 Mermaid 图 + 机制 / 源码结构 / 取舍 / 生产实践 / 竞品 / 双语文案）位于 `src/data/deep/{toolId}.ts`；
- 数据结构与类型契约位于 `src/data/deepDive.ts`；项目元数据与分层位于 `src/data/stack.ts`；
- 修正数据时请附官方文档或 GitHub 仓库链接作为依据，保持「数据截至 2026-07-18，仅供学习参考」的免责口径同步更新（如有必要）。

### 图例硬性约束（Mermaid 数据必须满足）

`src/data/deep/{toolId}.ts` 中的图例数据有以下硬约束，违反将导致渲染失败：

- 节点 label ≤ 8 个字符，sub ≤ 14 个字符；
- 边标签 ≤ 10 个字符；
- 节点 id 仅允许英文字母、数字与下划线；
- 禁止在 label / sub / 边标签中使用英文双引号（`"`）、分号（`;`）与冒号（`:`）。

### 提交前必做检查

```bash
# Mermaid 语法校验（64 张图全量）
npx tsx scripts/validate-diagrams.ts

# TypeScript 类型检查
npx tsc --noEmit -p tsconfig.app.json

# ESLint
npm run lint
```

三项全部通过后再提交 PR。

### PR 流程

1. Fork 本仓库，从 `main` 切出功能分支（建议命名 `fix/xxx` 或 `feat/xxx`）；
2. 提交信息简洁明确，说明「改了什么、为什么」；
3. 发起 PR 并关联相关 Issue（如有）；
4. 保持 PR 粒度小而专注：内容纠错与代码改动尽量分开提交。

### 代码风格

- 遵循仓库内 ESLint 配置（`npm run lint` 必须通过）；
- TypeScript 严格类型，避免 `any`；路径别名 `@/` = `src/`；
- 设计纪律：暖纸色系、低饱和配色、留白清晰；**禁止蓝紫渐变与高饱和背景**，新增 UI 需与现有视觉体系一致。

## English

Thank you for your interest in the **Agent Harness Stack Guide**. This project was generated by Kimi (Kimi-v3); community corrections and improvements are welcome. Please follow the conventions below.

### Reporting Bugs

1. Search existing Issues first to avoid duplicates.
2. When opening a new Issue, please include:
   - A clear description and reproduction steps (a minimal path is best);
   - Your environment (Node ≥ 20, OS, browser and version);
   - Expected behavior vs. actual behavior;
   - Error logs or screenshots (for Mermaid rendering issues, note the diagram index and tool ID).

### Content Corrections (Data & Docs)

Site content is maintained per project:

- Each project's deep content (four Mermaid diagrams + mechanism / source structure / trade-offs / production practices / competitors / bilingual copy) lives in `src/data/deep/{toolId}.ts`;
- The data contract lives in `src/data/deepDive.ts`; project metadata and layering in `src/data/stack.ts`;
- When correcting data, cite an official docs or GitHub link as the source, and keep the "data as of 2026-07-18, for learning reference only" disclaimer in sync where applicable.

### Diagram Hard Constraints (Mermaid data)

Diagram data in `src/data/deep/{toolId}.ts` must satisfy these hard rules; violations break rendering:

- Node label ≤ 8 characters, sub ≤ 14 characters;
- Edge label ≤ 10 characters;
- Node IDs may only contain letters, digits, and underscores;
- No English double quotes (`"`), semicolons (`;`), or colons (`:`) in labels / subs / edge labels.

### Required Checks Before Submitting

```bash
# Mermaid syntax validation (all 64 diagrams)
npx tsx scripts/validate-diagrams.ts

# TypeScript type check
npx tsc --noEmit -p tsconfig.app.json

# ESLint
npm run lint
```

All three must pass before opening a PR.

### Pull Request Flow

1. Fork the repo and branch off `main` (suggested names: `fix/xxx` or `feat/xxx`);
2. Write concise commit messages explaining what changed and why;
3. Open a PR and link the related Issue if any;
4. Keep PRs small and focused: separate content corrections from code changes.

### Code Style

- Follow the repo's ESLint config (`npm run lint` must pass);
- Strict TypeScript — avoid `any`; path alias `@/` maps to `src/`;
- Design discipline: warm paper palette, low-saturation colors, generous whitespace; **no blue-purple gradients or high-saturation backgrounds** — new UI must stay consistent with the existing visual system.
